# xiaokai SaaS V1

这是把现有无限画布从“单机工具”升级成“网页 SaaS”的第一版。

## 当前已经做好的网页结构

- `/`：产品首页
- `/login`：登录 / 注册
- `/dashboard`：用户工作台、云端项目列表
- `/workspace/:id`：原来的无限画布，已嵌入账户与云端项目系统
- `/billing`：积分充值页面
- `/transactions`：积分流水
- `/settings`：账户设置
- `/admin`：管理员数据概览（需要 `ADMIN_EMAIL`）

## 积分规则

用户看到的积分已经按你的想法缩小 10 倍：

- `¥1 = 10 积分`
- `¥10 = 100 积分`
- `¥50 = 500 积分`
- `¥100 = 1000 积分`

后台继续保留更细的整数单位：

- `10 internal units = 1 用户积分`

这样以后可以支持 4.5 积分这类价格，不会出现小数精度问题。

### 当前建议售价

- GPT Image 2：1K 3积分 / 2K 5积分 / 4K 8积分
- Nano Banana 2：1K 4积分 / 2K 6积分 / 4K 9积分
- Nano Banana Pro：1K 6积分 / 2K 6积分 / 4K 9积分

这些是 V1 的“用户售价配置”，后面会移到管理后台动态修改。

## 已经真正接上的 SaaS 能力

### 用户系统
- 邮箱注册
- 密码登录
- 30 天 Token 会话
- 账户角色 user / admin

### 积分钱包
- 可用积分
- 冻结积分
- 充值流水
- 生成冻结
- 成功消费
- 失败自动返还

### 真实模型生成 + 积分

生成流程已经变成：

```text
登录用户
  ↓
选择模型 / 分辨率 / 数量
  ↓
检查积分
  ↓
冻结积分
  ↓
提交 Kie
  ↓
成功：正式消费
失败：返还积分
```

### 云端画布

`/workspace/:id` 会把画布 JSON 保存到当前账户的云端项目记录里，同时继续保留原来的本地 IndexedDB 作为本地备份。

## 在线支付说明

当前 `/billing` 使用 **测试充值**，为了先把完整商业流程跑通。

正式上线前需要把：

`POST /api/wallet/dev-topup`

替换成真正的微信 / 支付宝 / Stripe 等支付回调。

生产环境请：

```env
NODE_ENV=production
ENABLE_DEV_TOPUP=false
```

## Windows 本地运行

1. 解压整个项目。
2. 双击 `start.cmd`。
3. 第一次会创建 `.env`。
4. 填写：

```env
KIE_API_KEY=你的真实 Kie Key
ADMIN_EMAIL=你自己的管理员邮箱
```

5. 保存 `.env`。
6. 再运行 `start.cmd`。
7. 打开：

```text
http://127.0.0.1:4318/
```

## 第一次测试顺序

1. 注册一个账户。
2. 打开“积分充值”。
3. 使用测试充值 ¥10 或 ¥100。
4. 返回工作台，新建画布。
5. 上传图片 → 生图节点 → 选择 GPT / Nano → 点击生成。
6. 打开“积分明细”，检查冻结 / 消费 / 返还记录。
7. 刷新画布或换浏览器标签，确认项目可以从云端重新打开。

## V1 数据库说明

为了让你现在最快测试，V1 使用本地 JSON 数据库：

```text
data/db.json
```

这适合本地验证，不适合正式商业上线。

真正上线时建议把用户、钱包、流水、项目改成 PostgreSQL / MySQL，并加入：

- 邮箱验证码 / 手机验证码
- 找回密码
- 真实支付订单
- 管理员加减积分
- 风控 / 限流
- 项目图片对象存储
- 数据库事务与并发扣费
- API 请求签名与日志

## 安全

- Kie API Key 仍然只在后端 `.env`
- 浏览器只持有 xiaokai 自己的登录 Token
- 不要把 `.env` 上传给客户或提交到公开仓库
